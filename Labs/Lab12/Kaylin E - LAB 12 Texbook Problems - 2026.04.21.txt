Question 1: Link the object files generated by p1.a, p2.a, p3.a in the following order: p1.o p2.o p3.o.

1a. Add the .start to properly mark the label startup as the entry point to our program.

1b. Resolve the external references by adding the proper .global, and .extern directives to the 3 files.

1c. Run the lcc on the .a files with the directives added to generate the three .o files. 
Make sure there are no errors when you try to link the three together using lcc p1.o p2.o p3.o.

1d. Append to the S, G, e, E, V, A tables based on the header entries in p1.lst.

1e. Append to the MCA (Machine Code Array) the hex code in p1.o.

1f. Same as 1d and 1e, but on p2.
Remember to adjust the addresses you add to the table based on the address that the code in p2 will start in the MCA.

1g. Same as 1d and 1e, but on p3. 
Remember to adjust the addresses you add to the table based on the address that the code in p3 will start in the MCA.

1h. Resolve the external references from the e table. 
(Modify the code at those locations in the MCA so that the pcoffset points to the correct location based on the address in the G table.)

1i. Resolve the external references from the E table.

1j. Resolve the external references from the V table.

1k. Write out the new header entries after linking. 
(Note that we only care about S, G, A along with o, C. Remember that V entries get rewritten as A entries after linking.) 
Check that your modified MCA is correct by running the lcc link.e (gets generated by linking) and checking link.lst.
